# Практическая работа № 4 — Потоки и процессы (вариант B)

## Цель
Сравнить вычислительную задачу в одном потоке, четырёх потоках и четырёх процессах; сравнить последовательный и параллельный ввод-вывод; показать различие между общей памятью потоков и отдельных процессов.

## Файлы
- `prepare_data.py` — создаёт `numbers.txt` (по умолчанию 10 млн целых чисел) и 20 файлов для сетевого теста.
- `benchmark.py` — измеряет медианное время трёх запусков CPU-задачи и, по запросу, загрузки 20 файлов.
- `shared_memory_demo.py` — демонстрирует отдельную память процессов и явную передачу данных через shared memory.

Используются только стандартные модули Python 3.11+; сторонние пакеты не нужны.

## Запуск в Ubuntu 22.04+

Перейти в корень репозитория и выполнить:

```bash
python3 pr04/prepare_data.py
python3 pr04/benchmark.py
```

Генерация 10 млн чисел создаёт большой текстовый файл. Для быстрой проверки можно сгенерировать 100 000 чисел:

```bash
python3 pr04/prepare_data.py --count 100000
python3 pr04/benchmark.py
```

### Сетевой тест (20 URL)

В первом терминале запустить локальный HTTP-сервер:

```bash
python3 -m http.server 8000 --directory pr04/web_data
```

Во втором терминале выполнить:

```bash
python3 pr04/benchmark.py --network
```

### Разделяемая память

```bash
python3 pr04/shared_memory_demo.py
```

## Что измеряется
- CPU: сумма всех чисел одним потоком, четырьмя потоками и четырьмя процессами.
- Network I/O: получение 20 локальных файлов последовательно, через `ThreadPoolExecutor` и через `ProcessPoolExecutor`.
- Каждый замер повторяется три раза; выводится медиана. CPU-результаты дополнительно проверяются на совпадение.

### Выводы
1. В CPython потоки обычно не ускоряют CPU-bound вычисления из-за GIL: в один момент байткод Python исполняется одним потоком интерпретатора. Дополнительные потоки также создают накладные расходы.
2. Несколько процессов могут выполнять вычисления на разных ядрах, но создание процессов и передача данных между ними стоят времени и памяти.
3. Потоки полезны для I/O-bound задач: пока один поток ожидает ответ, другой может выполнять запрос. Для маленьких файлов на локальном сервере ускорение может быть небольшим из-за накладных расходов.
4. Процессы имеют отдельные адресные пространства. Обычное изменение списка в дочернем процессе не меняет список родителя. Для совместного доступа можно использовать `multiprocessing.shared_memory`, при необходимости добавляя синхронизацию.
5. Для корректного сравнения необходимо использовать одинаковые входные данные и число повторов; результаты времени в отчёте должны быть получены фактическим запуском.

## Контрольные вопросы

**1. Что общего у потоков одного процесса и что у каждого своё?**  
Потоки одного процесса совместно используют адресное пространство, код, глобальные данные и открытые файлы. У каждого потока есть собственные стек, регистры и состояние выполнения.

**2. Почему в CPython 4 потока не ускорили счёт, а 4 процесса ускорили?**  
GIL ограничивает параллельное исполнение Python-байткода потоками внутри одного процесса. Отдельные процессы имеют отдельные интерпретаторы и могут работать параллельно на нескольких ядрах, хотя расходы на запуск и обмен данными могут уменьшить выигрыш.
