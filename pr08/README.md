# Практическая работа № 8 — Операционные системы — Вариант B

## Цель
Алгоритм банкира с откатом небезопасных запросов, поиск циклов в графе ожидания, TrackedLock и «обедающие философы».

## 1. Алгоритм банкира
```bash
python3 banker.py bank1.json
python3 banker.py bank2.json
```
После вывода Need и безопасной последовательности вводите запросы как `PID r1 r2 r3`; Ctrl+D завершает ввод. Запросы проверяются по Need и Available, затем проверяется безопасность. Если состояние небезопасно, выделение ресурсов откатывается.

## 2. Детектор deadlock
```bash
python3 deadlock_detector.py events.txt
```
Журнал использует строки `acquire THREAD LOCK`, `release THREAD LOCK`, `wait THREAD LOCK`. DFS ищет цикл в графе ожидания.

## 3. TrackedLock
```bash
python3 tracked_lock.py
python3 deadlock.py
python3 deadlock_fixed.py
```
Обёртка демонстрирует обнаружение цикла в графе ожидания. `deadlock.py` показывает небезопасный порядок захвата, а `deadlock_fixed.py` устраняет его единым порядком A → B. Это учебный пример; в реальном проекте необходимы более полное отслеживание владения и обработка таймаутов.

## 4. Обедающие философы
```bash
python3 philosophers.py --strategy ordered
python3 philosophers.py --strategy room
python3 philosophers.py --strategy deadlock
```
- `ordered`: единый порядок захвата вилок предотвращает циклическое ожидание.
- `room`: за столом одновременно могут конкурировать не более четырёх философов.
- `deadlock`: демонстрирует небезопасный подход; зависание возможно, но не гарантируется в каждом запуске.

## Вывод
Банкир выдаёт ресурсы только при безопасном состоянии. Цикл в графе ожидания указывает на взаимоблокировку. Единый порядок блокировок или ограничение числа философов предотвращает классический deadlock.
